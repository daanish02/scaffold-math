## Intuition

A matrix isn't just a grid of numbers - it's an instruction for moving every point in the plane at once. Feed it a vector, and it hands back a new vector: stretched, squashed, rotated, or flipped. Multiplying a matrix by a vector is applying that move to a single point; multiplying two matrices is chaining two moves into one.

## Formal definition

A matrix{" "}
<SymbolTooltip client:visible name="matrix" pronunciation="A" meaning="a rectangular array of numbers representing a linear map">$A$</SymbolTooltip>{" "}
of size $m \times n$ maps vectors in $\mathbb{R}^n$ to vectors in $\mathbb{R}^m$ by:

$$
(Av)_i = \sum_{j=1}^n A_{ij} v_j
$$

This map is **linear**: $A(u + v) = Au + Av$ and $A(cv) = cA(v)$ for any scalar $c$. In fact every linear map between finite-dimensional vector spaces can be written as matrix multiplication once a basis is fixed - matrices and linear maps are the same object viewed two ways.

**Composition**: applying $A$ then $B$ to a vector equals applying the single matrix $BA$ - matrix multiplication is defined exactly so that $(BA)v = B(Av)$.

## Common pitfalls

<Callout label="Common pitfall">
  Matrix multiplication doesn't commute: $AB \neq BA$ in general. Order matters because it encodes *which transformation happens first* - applying a rotation then a shear is a different move than shear-then-rotation.
</Callout>

<Callout label="Common pitfall">
  $A$ and $v$ must have compatible shapes: an $m \times n$ matrix only acts on vectors in $\mathbb{R}^n$. "Multiplying" a $2\times2$ matrix by a 3-vector isn't a smaller version of the same operation - it's undefined.
</Callout>
